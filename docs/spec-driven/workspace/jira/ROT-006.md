## Description

As a user, I want to choose how I fill out the project form — from a classic stacked layout to a poetic sentence-style to a seed packet aesthetic — so adding a project feels intentional and personal to my creative mood.

## Acceptance Criteria

1. Given the project form modal is open, then a style picker is visible in the modal header with 6 options.
2. Given the user selects a style, then the form re-renders in that style without losing any partially-entered field values.
3. Given the user closes and reopens the modal, then the previously selected style is restored.
4. Given a page reload, then the preferred form style persists (stored in GardenState → idb-keyval).
5. Given each of the 6 styles, when the user completes and submits, then the project is created correctly.
6. Given the Live Preview style, when the user types in any field, then the preview card updates in real time.
7. Given the Two-Beat style, when the user completes Step 1, then Step 2 appears with a smooth transition.
8. Given the style picker, then all styles are keyboard accessible (Tab, arrow keys, Enter).

## Tech Lead notes (Pass 2, informed by Feature TDD FTDD-006)

- `formStyle: FormStyle` already in `GardenState` via Feature TDD — persists via idb-keyval (ADR-003)
- `SET_FORM_STYLE` action in `GardenAction` type
- `FormStylePicker` renders in `Modal`'s `headerAction` prop (ADR-005)
- Live Preview requires `size="lg"` on Modal
- Each style component receives `FormStyleProps` — all fields + setters + handlers
- State lifted to `ProjectForm` container — switching styles preserves all field values
- **Do not reset field values on style switch** — this was a high-stakes design decision resolved in Dead Reckoning
