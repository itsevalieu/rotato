# ADR-004: dnd-kit for Drag and Drop

| Field | Value |
|---|---|
| **Status** | Accepted |
| **Date** | Stage 4 — Architecture |
| **Author** | Tech Lead |
| **Confidence** | 🟡 AMBER |

## Context

ROT-003 (P0) requires drag-and-drop. Options:
- **dnd-kit** — actively maintained, accessible, works with Next.js
- **react-beautiful-dnd** — deprecated, no longer maintained
- **react-sortable-hoc** — deprecated
- **Custom implementation** — significant effort for no gain

## Decision

Use **dnd-kit**.

## Consequences

- Adds `aria-describedby` attributes to draggable elements on the **client only** — not present in server render
- This causes a hydration mismatch unless draggable components are wrapped in a client-side mounting guard
- **Required pattern for all dnd-kit draggable components:**
  ```tsx
  const [mounted, setMounted] = useState(false)
  useEffect(() => setMounted(true), [])
  if (!mounted) return <StaticCard {...props} />
  return <DraggableCard {...props} />
  ```
- **Enforce via Bugbot:** flag `useSortable` or `DraggableItem` without mounting guard pattern

🟡 AMBER — standard library choice; SSR behavior not spec'd. The mounting guard requirement was identified during Confidence Map review and became part of ADR-006.
