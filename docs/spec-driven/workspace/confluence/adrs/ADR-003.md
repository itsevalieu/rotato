# ADR-003: IndexedDB via idb-keyval for Persistence

| Field | Value |
|---|---|
| **Status** | Accepted |
| **Date** | Stage 4 — Architecture |
| **Author** | Tech Lead |
| **Confidence** | 🟢 GREEN |

## Context

The PRD is explicit: local-first, no backend, no account system (RT-003 from Red Team audit). Need browser-based persistence. Options:
- **localStorage** — 5MB limit, synchronous, string-only
- **IndexedDB directly** — powerful but verbose API
- **idb-keyval** — minimal wrapper around IndexedDB, async, simple key-value interface
- **Dexie** — full ORM over IndexedDB, more than needed

## Decision

Use **idb-keyval**. Store the entire `GardenState` object under `STORAGE_KEY`.

## Consequences

- Storage limit ~50-250MB (vs ~5MB for localStorage)
- Async read/write → requires hydration pattern: initial render shows loading state until `HYDRATE` action fires with loaded state
- `state.hydrated` flag used throughout components to prevent flash of empty content
- **Not available in private browsing** — graceful degradation required (Red Team finding RT-004)
- **Enforce via `architecture.mdc` rule and Bugbot:** no direct `localStorage` calls except `ONBOARDING_KEY`

## Confidence note

🟢 GREEN — local-first persistence is explicitly required by the PRD as a permanent constraint.
