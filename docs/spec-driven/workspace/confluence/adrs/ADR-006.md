# ADR-006: SSR Hydration Guards

| Field | Value |
|---|---|
| **Status** | Accepted |
| **Date** | Stage 4 — Confidence Map review |
| **Author** | Tech Lead |
| **Confidence** | 🔴 RED → resolved |

## Context

Three components caused hydration mismatches in development. All three were identified as **RED items** on the Confidence Map — SSR behavior was never spec'd in the PRD, and the team assumed client-only rendering without stating it.

The three violations:

| Component | Issue |
|---|---|
| Seed data / project cards | `Date.now()` generates different values on server vs. client |
| Date display (e.g. "last touched") | `toLocaleString()` formats differently by locale on server vs client |
| dnd-kit draggable components | `aria-describedby` attributes added by dnd-kit only on the client |

## Decision

Three mitigation patterns, applied consistently:

**Pattern 1 — `suppressHydrationWarning`**
For elements rendering dynamic date/time values that differ between server and client:
```tsx
<span suppressHydrationWarning>
  {project.lastTouchedAt}
</span>
```

**Pattern 2 — Client-side mounting guard**
For dnd-kit draggable components:
```tsx
const [mounted, setMounted] = useState(false)
useEffect(() => setMounted(true), [])
if (!mounted) return <StaticCard {...props} />
return <DraggableCard {...props} />
```

**Pattern 3 — Hydration state check**
For components reading persisted GardenState:
```tsx
if (!state.hydrated) return <LoadingSkeleton />
return <Board projects={state.projects} />
```

## Consequences

- Brief flash of loading/skeleton state on initial load — acceptable and intentional
- Zero hydration errors in production after these patterns are applied
- **All three patterns encoded in `architecture.mdc` rule** — new developers cannot violate them unknowingly
- **Bugbot detects** `Date.now()`, `toLocaleString()`, and dnd-kit components without the guard pattern

## Confidence note

🔴 RED (original) → resolved. This ADR documents the resolution of a Confidence Map RED item. SSR behavior should have been explicitly addressed at Stage 2 (PRD) or Stage 4 (Architecture). It was not, and the cost was three production bugs. The `architecture.mdc` rule prevents recurrence.
