## Approach overview

The project form needs 6 visually distinct layouts that share a single data contract. The key architectural insight: field state must live in a **parent container** (`ProjectForm`) and flow down to **presentational style components**. Switching styles unmounts and remounts the child component — but because state lives in the parent, all field values survive the switch.

This is a pure UI problem. No new backend. No schema changes beyond adding `FormStyle` to `GardenState`.

## Interface changes

```typescript
// New type — src/lib/types.ts
type FormStyle =
  | "classic"
  | "sentence"
  | "seed-packet"
  | "two-beat"
  | "envelope"
  | "live-preview";

// GardenState addition
interface GardenState {
  // ...existing fields
  formStyle: FormStyle;
}

// New action
| { type: "SET_FORM_STYLE"; style: FormStyle }

// New shared interface — form-styles/types.ts
interface FormStyleProps {
  title: string; setTitle: (v: string) => void;
  description: string; setDescription: (v: string) => void;
  section: SectionId; setSection: (v: SectionId) => void;
  color: string; setColor: (v: string) => void;
  icon: string; setIcon: (v: string) => void;
  tags: string[]; setTags: (v: string[]) => void;
  nextTinyStep: string; setNextTinyStep: (v: string) => void;
  isEditing: boolean;
  onSubmit: () => void;
  onClose: () => void;
}
```

## Vertical slice guidance

**Single ticket (ROT-006 — 8 points).** All pieces are tightly coupled:
- The type changes must exist before the context changes
- The context changes must exist before the picker
- The picker is useless without at least one style component
- The `FormStyleProps` interface must exist before any style component

Splitting further creates unusable partial implementations. Use logical **commit** grouping instead of ticket splitting:
1. Types + context (can be reviewed independently)
2. 6 style components (reviewable as a batch)
3. Picker + container wiring + Modal props (the integration commit)

## Applicable ADRs

- **ADR-002**: state in GardenContext via `SET_FORM_STYLE`, not a component-level store
- **ADR-003**: `formStyle` persists via idb-keyval (it's in `GardenState`), not direct localStorage
- **ADR-005**: Modal `size` + `headerAction` props — added specifically for this feature at Gate 2
